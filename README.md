# PANCAKE AXEL

Three.js + TypeScript + Viteで動く、60秒のパンケーキ空中演技ゲーム。
外部API、有料アセット、サーバー、外部フォントは不使用。モデル・焼き色テクスチャ・効果音はプログラムで生成します。

## 起動

```sh
npm ci
npm run dev
```

## 操作

- 開始時にセンサー権限と実データを確認し、モーション操作を標準で使用します。非対応・権限拒否・データ途切れの場合だけタッチ操作に切り替えます。
- 手首を返してトス。投げる瞬間の加速度が高さ、返す回転速度が回転数、ひねりが横回転と方向を決めます。空中で回転を追加・変更できません。
- 飛行中は左右に傾けてフライパンを落下位置へ。水平に戻してキャッチします。位置・水平の許容幅を設けています。
- 代替操作はトスボタンを長押しして離す方式。ためる長さで高さと回転数、横に払って離すとひねり、上に払うと回転を強めます。飛行中のボタンは左右移動だけです。
- 代替操作では画面ドラッグと矢印キーでもフライパンを移動できます。Spaceでためてトスできます。
- スマホは手から離さず、小さな動きで。水平校正、感度、左右の手の設定は一時停止画面にあります。
- 縦横画面の座標補正、誤検知抑制、連続トス防止を実装。画面方向変更時は一時停止して再校正。タブ非表示でも停止します。

技名カットインは着地時の1回。画面の左外から入り、右外へ抜け、着地評価と加点を表示します。制限時間直前の着地も、カットイン終了後に結果画面へ移ります。

## 採点と仕様

技術点は成功するたびに積算し、技術点・総合点に1000点の上限は設けません。総合は `round(sqrt(技術 × 芸術))`。
技術点は技の難度 × 着地品質 ÷ (1 + 同じ技の既出回数 × 0.45)。
芸術点は表裏の焼成品質の幾何平均 × 形の保持率 × 1000（焼き上がり品質の換算基準）。技術点が1000を超えても、焼き加減に応じて総合点を計算します。
各面20秒が理想。20秒超過で品質が低下し34秒で0。空中では焼けません。
トス時の回転速度を半回転・1.5回転・2.5回転・3.5回転に補助し、投げた後は一定の角速度で回転します。ひねり付きの投げ方では横方向の1回転を組み合わせます。
大技ほど横流れが増え、着地時の位置ずれやフライパンの傾きで技術点と形の保持率が低下。生地投入直後の3秒未満のトスも形が崩れます。
制限時間内に着地できなかった演技は加点せず、形の保持率を減らします。
投げ続けると生焼け、放置すると焦げ、焼くだけでは技術点0。バランスよく焼いて複数の技を使う必要があります。

企画書の暫定5演技制は今回の要望に合わせて時間制に変更。
オンラインランキング・リプレイ・音声実況は未実装。ベストスコアは端末内保存。
結果から1080×1080のPNGスコアカードを生成。表裏のパンケーキ、総合・技術・芸術点、短文、ハッシュタグ、URLを画像にも載せます。
共有はWeb Share APIでPNGと投稿文をまとめて渡します。URLは投稿文内に含め、別のurl属性を渡して本文が落ちる経路を避けます。
画像共有非対応時は本文を共有し、カード保存・文章コピーから手動で画像を添付できます。共有API非対応時はカード保存と投稿文コピーへ切り替えます。
共有先アプリによって画像と文章の受け取り方が違うため、明示的な「カード画像を保存」「文章をコピー」も用意。X投稿リンクには得点・短文・ハッシュタグ・URLを含めます。
センサーはHTTPSと実機権限が必要。未対応・拒否時もタッチでプレイ可能。
モーションの感度と端末差はiOS/Androidの実機検証が必要です。

## GitHub Pagesへ公開

1. このフォルダをGitHubの公開リポジトリのmainブランチにpush。
2. リポジトリの Settings → Pages → Source を GitHub Actions に設定。
3. Actionsの「Deploy to GitHub Pages」を実行（以後mainへのpushで自動公開）。

Viteのbaseを相対パスにしているため、リポジトリ名付きURLにも対応。
GitHub Freeの公開リポジトリと標準のPages URLを使用すれば有料サービス不要。
公開先: https://cadmium2525.github.io/pancake/
リポジトリ: https://github.com/cadmium2525/pancake
mainへのpush後、Actionsが成功すると公開サイトに反映されます。

```sh
npm test
npm run build
npm run preview
```

採点・焼成・時間切れ・現実的な金メダル到達経路を自動テスト。
UIとWebGLの確認は実ブラウザで実施。ソースはsimulation（ゲームルール）、render（描画とカメラ）、main（入力とUI）に分離。
